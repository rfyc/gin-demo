# 修改或添加代码的规则（高优先级）

## 输出内容必须使用简体中文
- 思考过程/Thought/Thinking必须使用简体中文
- 输出结果必须使用简体中文
- MEMORY.md 中的内容必须使用简体中文

## Go 技能体系

编写/修改/审查/重构 Go 代码时，必须遵循 .claude/skills/golang/coding/SKILL.md 中的强制规范（函数格式、注释、日志、测试）。

- **coding**: 强制规范与惯用模式（写代码时遵循）
- **testing**: 编写测试时调用（单元测试、表驱动）
- **review**: 提交/审查前调用（逻辑审核、并发安全、错误处理、安全性）
- **hotfix**: 排查修复线上问题时调用（失败测试复现、根因定位、最小修复），不属于功能开发流程
- **where**: 运行 go 命令前调用（定位与 go.mod 匹配的 go 版本）

## 功能开发流程

开发一个新功能时，按下述步骤顺序执行，上一步未完成不得进入下一步：

1. **需求确认**: 明确功能目标、输入输出、异常场景与验收标准；有歧义先与用户确认，不臆测需求
2. **方案设计**: 确定涉及的文件、包、数据模型与接口，复杂功能先简述方案再动手
3. **基线检查**: 开发前确认 go build ./...、go vet ./... 基线通过（已知失败除外），便于区分既有问题与新引入的回归
4. **代码实现**: 按 coding 强制规范编写（ctx 首参、var 声明、注释、日志、错误包装），功能拆分为小步完成
5. **单元测试**: 每个新函数补充单元测试，按 testing 规范覆盖正常/边界/异常场景并完成验证，未通过不得视为完成
6. **代码审查**: 调用 review 对变更全面审查，修复发现的问题
7. **变更汇总**: 整理变更，向用户汇报功能内容与验证结果；
